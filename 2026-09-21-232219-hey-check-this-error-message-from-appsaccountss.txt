⏺ It's a false positive from the type checker, not a real bug — your code runs
  fine.

  Why it happened: line 2 imported your custom User, but line 7 rebound it with
  User = get_user_model(). Type checkers (django-stubs / PyCharm) type
  get_user_model() as returning Django's built-in User, whose manager signature
  is create_user(username, email=None, password=None, **extra). So it checked
  your call against that signature and complained about the missing username.

  Your actual manager (apps/accounts/managers.py:18) is create_user(self, email,
  password=None, **extra_fields) — no username at all, and your model sets
  username = None with USERNAME_FIELD = 'email'.

  Fix applied — dropped the redundant rebinding in apps/accounts/serializers.py,
  so User stays the concrete class imported on line 2 and the checker resolves
  UserManager.create_user correctly:

  from .models import User, EmailVerificationOTP   # unchanged
  # removed: from django.contrib.auth import get_user_model
  # removed: User = get_user_model()

  Within the accounts app itself, importing the model directly is safe
  (get_user_model() mainly matters in other apps to avoid coupling/import-order
